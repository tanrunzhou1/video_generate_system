# 基础设计文档：剧本驱动的多模态短片生成系统

## 1. 项目概述

- 项目名称：剧本驱动的多模态短片生成系统
- 项目目标：根据剧本 + 人物设定（图片与文档）自动生成 1-3 分钟短片
- 输出内容：分镜画面（图片/片段）、角色配音、字幕、背景音乐、最终合成视频
- 项目定位：强调工程落地能力的多媒体系统，支持中间结果可控与可编辑

## 2. 核心输入与输出

### 输入

- 剧本（故事文本、台词、场景结构）
- 人物设定图（每个角色的参考图）
- 人物设定文档（性格、说话风格、外观约束）
- 可选风格参考（画面风格、节奏、情绪）

### 输出

- 分镜规划（场景拆分、镜头意图、时长、角色出场）
- 每个镜头的视觉素材（图片或短视频片段）
- 每段台词/镜头的语音音频
- 字幕文件
- 背景音乐匹配结果
- 最终渲染短片

## 3. 架构决策：以 Workflow 为主

系统采用 **Workflow 主干 + 局部 Agent 增强** 的架构。

- 主策略：`80% workflow + 20% agent`
- 选择 workflow 的原因：
  - 流水线阶段清晰、稳定性高
  - 更容易重试、追踪和排错
  - 更适合课程项目交付与答辩演示
- 可引入 agent 的位置：
  - Prompt 润色
  - 失败镜头自动修复建议
  - 背景音乐推荐与重排序

## 4. 高层流程

1. 剧本解析与场景切分
2. 分镜生成（镜头列表与提示词）
3. 角色一致性约束注入（参考图与设定）
4. 视觉生成（每个镜头生成图片或短片）
5. 语音生成（多角色 TTS）
6. 字幕生成与时间对齐
7. BGM 选择与时长适配
8. 视频合成与导出（FFmpeg）
9. 基础质量检查与失败回退

## 5. 推荐技术栈（MVP）

### 编排与后端

- 工作流引擎：LangGraph（后续可升级 Temporal/Celery）
- API 服务：FastAPI
- 异步任务（可选）：Celery + Redis

### 多模态模型

- 剧本理解/分镜规划：LLM（OpenAI/Qwen/Claude 等）
- 图像生成：SDXL 或 FLUX
- 语音生成：XTTS / Edge-TTS / ElevenLabs
- 可选视频生成：Runway/Pika/Luma API 或开源视频模型

### 检索与一致性

- 向量特征模型：CLIP（用于角色/风格相似度）
- 向量索引：FAISS（MVP）或 Milvus（可扩展）

### 媒体处理

- 合成渲染：FFmpeg
- 字幕处理：SRT 工具链 + 时间戳对齐工具
- 素材存储：本地文件系统（MVP），后续可接对象存储

### 前端（MVP 可选）

- 框架：React 18
- 工程框架：@umijs/max（Umi/Max）
- UI 体系：Ant Design 5 + @ant-design/pro-components
- 数据请求与状态：umi-request + @tanstack/react-query
- 媒体预览：原生 `<video>`（MVP），可选 video.js
- 功能：输入表单、任务状态、中间结果编辑、成片预览与下载

## 6. 非功能需求

- 可复现性：固定随机种子 + 提示词模板，提升角色一致性
- 稳定性：阶段级重试策略 + 失败降级方案
- 可观测性：按阶段记录日志、任务 ID、错误原因、耗时
- 可扩展性：各生成阶段支持模型提供方可插拔

## 7. MVP 范围边界

### 范围内

- 短剧本端到端自动生成
- 角色一致性约束下的分镜画面生成
- 多角色配音
- 字幕 + BGM + 最终视频导出

### 暂不纳入（第二阶段）

- 超过 3 分钟的长片与复杂镜头运动控制
- 实时交互式时间线编辑器
- 完整生产级版权与合规自动化体系

## 8. 评估指标（面向演示与答辩）

- 画面质量：主观评分 + 基础清晰度/完整性检查
- 角色一致性：跨镜头相似度 + 人工评分量表
- 叙事连贯性：镜头与剧本文本的一致程度
- 音画同步：字幕与配音时间匹配准确性
- 流水线成功率：完成任务数 / 提交任务数

## 9. 风险与应对

- 风险：角色跨镜头漂移
  - 应对：参考图约束 + 提示词模板 + 固定 seed 策略
- 风险：生成耗时波动大
  - 应对：异步队列 + 超时控制 + 重试 + 降级素材
- 风险：输出质量不稳定
  - 应对：在终渲染前提供中间结果人工复核与编辑
